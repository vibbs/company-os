# Plan: Harden the 1.12.0 release

**Spec (binding):** the user's request — "address the open points, ensure the new release is holistically strong, then raise a PR." Context: branch `docs/end-user-review` already holds the end-user docs/diagram overhaul (plan `tasks/plans/2026-10-13-end-user-docs-overhaul.md`), version 1.12.0, CHANGELOG `[1.12.0]`.

Open points carried from round 1:
- K-M8: install.sh conflict copies are named by file name only, so two conflicted files with the same name collide.
- K-M4: `lift_claude_fields` (tools/build/build-claude.sh) silently skips `runtimes: # comment` and CRLF frontmatter.
- No automated shell tests or CI; every check so far was manual.
- 7 tool scripts print custom help that bypasses the shared printer (drift risk).
- S19: user-facing skills bury "When to Use" under metadata. S20: upgrade skill hard-codes the raw GitHub URL with no pin/review option. S21: validator warnings use non-ASCII symbols and exit 0 even with warnings.
- Setup skill Step 10 table omits the legacy root files (TOKEN_COSTS.md, FAQ.md, SETUP_COMPANY_OS.md) that setup.sh removes.
- No CONTRIBUTING.md or SECURITY.md for a public repo.

## Global Constraints
1. Source of truth is `os/`; after editing `os/` or `CLAUDE.md` run `bash tools/build/build.sh` and commit regenerated adapters in the same commit.
2. Bash 3.2 compatible (macOS `/bin/bash`): no `${v,,}`/`${v^^}`, no associative arrays, no `mapfile`/`readarray`, guard empty arrays under `set -u`; every grep that may match nothing is guarded under `set -euo pipefail`.
3. No new runtime dependencies for users. Tests may use only bash, coreutils, git, tar, node (already used by docs/diagrams), python3 (optional; skip a test with a clear SKIP line if absent).
4. Counts: 64 skills, 9 agents, 33 runnable tool scripts (excluding `tools/build`, `tools/lib`); version `1.12.0`. Field spelling `user-invocable` (legacy `user-invokable` accepted as alias).
5. User-facing assets live in `.company-os/docs/` (guides, `diagrams/*.svg`, `SKILL_SCHEMA.md`).
6. Conventional commits, subject ≤72 chars, body explains why, trailer `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. **Never push, tag, or create releases/PRs** — the controller does that.
7. Plain-language docs: short sentences, active voice, define jargon once.
8. Verification before DONE: `bash tools/build/build.sh --check` (0 fail, 0 warn), `node docs/diagrams/render.js --check`, and (after Task 2 exists) `bash tests/run.sh` all green; show output in the report.

## Task 2: Automated tests and CI

Files: `tests/**` (new), `.github/workflows/ci.yml` (new), `install.sh` (local-source hook only), docs that mention testing.
- Add an official local-source option to install.sh for offline installs and tests: env `COMPANY_OS_SOURCE=<path to a checkout or .tar.gz>` skips the GitHub download and uses that source (with the same extracted-directory handling). Document it in CUSTOMIZING (for maintainers) and TROUBLESHOOTING (offline/air-gapped installs).
- `tests/run.sh`: zero-dependency runner. Discovers `tests/test_*.sh`, runs each in a subshell, prints `PASS/FAIL/SKIP name`, a summary, exits non-zero on any failure. `tests/lib/assert.sh` with `assert_eq`, `assert_contains`, `assert_file_exists`, `assert_exit`. Works under macOS `/bin/bash` 3.2.
- Test files (each self-contained, using temp dirs; never touch the working tree):
  - `test_config.sh` — `cfg_get` on the shipped config and on fixtures (comments, quotes, CRLF, nested keys, missing keys).
  - `test_tools_help.sh` — every runnable tool script, the build scripts and validators: `--help` and `-h` exit 0 and print a Usage line, with no side effects (git status unchanged).
  - `test_artifacts.sh` — validate.sh (single file, `--all`, bad file), link.sh/promote.sh on temp artifacts, check-gate.sh stage behavior (idea advisory → 0, growth enforced → 1, missing artifact → 2).
  - `test_build.sh` — `build.sh --check` clean; generated `.claude/skills/*/SKILL.md` match a fresh build into a temp copy; lift handles fixtures (CRLF, commented `runtimes:`), legacy `user-invokable` alias lifts to `user-invocable`.
  - `test_diagrams.sh` — `node docs/diagrams/render.js --check` (SKIP if node missing).
  - `test_docs.sh` — every relative Markdown link and image in README.md, CLAUDE.md, os/**/*.md, .company-os/docs/**/*.md, docs/**/*.md resolves; every `/command` in README matches a skill name; README's Commands table equals the set of skills with `runtimes.claude.user-invocable: true`; counts in README match the filesystem.
  - `test_install.sh` — using `COMPANY_OS_SOURCE` with a `git archive HEAD` tarball: fresh install into a temp git repo for `--runtime claude`, `cursor`, `core`; expected files present (adapters per runtime, tools/lib, .company-os/docs/diagrams/*.svg, reference standards); links in installed `.company-os/docs` resolve; upgrade with a locally modified guide produces the `.user` copy and refreshed doc; `--dry-run` writes nothing; two same-named conflicted files do not collide (K-M8); `--check` reports versions.
- `.github/workflows/ci.yml`: on push and pull_request; matrix `ubuntu-latest` and `macos-latest`; on macOS run the suite explicitly with `/bin/bash tests/run.sh` (bash 3.2); setup-node for diagrams; also `bash tools/build/build.sh --check --strict`. Pin action versions to major tags that exist (`actions/checkout@v4`, `actions/setup-node@v4`).
- Fix any real bug the tests expose (small, focused commits, explain in the report).
