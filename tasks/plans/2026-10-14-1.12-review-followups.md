## Task 1: Installer and build correctness

Files: `install.sh`, `tools/build/*.sh`, `tools/registry/install-runtime.sh`, tests, CHANGELOG.
- F1 (review score 50, data safety): manifests written by older installers (roughly 1.4–1.8; commits 839ab27, d134931) hashed files on disk after install, including user edits kept by a non-force re-run. install.sh still accepts them as the merge base (`.company-os/manifest`, `.company-os-manifest`), so an old edit reads as "unedited" and is overwritten with no `.user` copy. Fix: a manifest without the new template-hash header marker is untrusted; take the no-manifest path (forced backup, `.user` copies on `--force`, no false stamp). Test with a synthetic old-style manifest that records an edited file's hash.
- F2 (score 75): `--runtime` validation. Every name in a comma list must be one of claude, cursor, codex, gemini, aider, or the whole value must be one of all, auto, core. `all`/`auto`/`core` inside a comma list are an error (or expand `all` — choose one, document it). Unknown names (e.g. `claud`) print an error listing valid values and exit 1 before writing anything. Help text matches. Same validation in `tools/registry/install-runtime.sh`, which must also accept `aider` (it only needs AGENTS.md) and stop advertising the undocumented `agents` value or document it; fix its header claim "does NOT touch any other runtime adapters" for `all`.
- F3 (score 75): `build.sh --runtime=gemini|codex` (and `build-gemini.sh` / `build-codex.sh` run directly) must rebuild AGENTS.md first when anything it is built from changed (os/skills, os/agents, tools/, CLAUDE.md) — simplest correct fix: always regenerate AGENTS.md before Gemini/Codex output. Test: edit an os/ skill description in a temp copy, build gemini only, assert GEMINI.md contains the new text.
- F4 (score 75): `tools/build/validate-skill.sh` declares `KNOWN_FIELDS` and the comment promises "any other top-level key is allowed but warned", but nothing warns. Implement the warning (so `--strict` fails on a typo like `user-invocabel:`), keeping legacy `user-invokable` handling. Make sure all 64 shipped skills stay warning-free. Same check for agents if validate-agent.sh has the same gap. Test with a fixture.
- F5 (score 50): `install.sh` header and `--help` say edited files are kept by default and copies go under `.company-os/conflicts/`; guides in `.company-os/docs/` are refreshed on a version upgrade and the edit is saved as `<name>.user` next to the file. Make header, `--help` and the `--backup` line (backup is also automatic when there is no trusted manifest) accurate.
- F6 (score 50): `build-agents-md.sh` writes "Source: .claude/ + CLAUDE.md" into AGENTS.md (source is `os/` + CLAUDE.md), and its Tool Catalog says "Safe to invoke directly" while listing sourced helpers (`tools/lib/*.sh`, `tools/build/lib-*.sh`). Exclude sourced helpers from the catalog (or list them under a separate "helpers, do not run" line) and fix the source header. Rebuild adapters.
